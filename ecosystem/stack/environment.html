How Codeless Bridge ships things

Every project goes from an idea to a live URL on codelessbridge.com the same way, with errors, analytics and uptime checks from its first deploy. This page explains each part, why it was chosen, what the alternative is, and what's still left to set up.

The wiring

One domain, many projects, shared watchers

Visitors only ever see codelessbridge.com. Cloudflare answers "where does this name live?", Vercel serves each project, and three services watch every deploy. GitHub only stores code; it never serves anything public.

The routine

From idea to live URL

The same five moves for every project. The full checklist is in stack/docs/new-project.md.

  1. Pick a template

    Browser-only demo → template-vite. Accounts, data or server code → template-next.

  2. Create the repo

    "Use this template" on GitHub. It arrives with lint, CI, telemetry and agent rules already wired.

  3. Import in Vercel

    Paste env vars from 1Password. Every push to main deploys; every PR gets a preview link.

  4. Add a subdomain

    Vercel shows a CNAME; add it in Cloudflare with the proxy off. HTTPS is automatic.

  5. Switch on watchers

    Sentry and PostHog keys in Vercel, a Better Stack monitor. Done means one test error and one pageview arrived.

Weekly review

Every Monday an agent re-checks each layer: new major versions, pricing or free-tier changes, deprecations, security notices, and whether a "switch when" signal has happened. Changes arrive as a pull request on jaablesa/stack that updates this page and DECISIONS.md; nothing switches without your approval.
